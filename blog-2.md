# How `Pick` and `Omit` Help You Stop Repeating Yourself in TypeScript

## Introduction

One thing I didn't understand when I started TypeScript was why people kept talking about "don't repeat yourself" (DRY). I really did not understand the importance of it

Then I discovered `Pick` and `Omit` — which is shown in the Module 2.
 two built-in TypeScript utility types — and suddenly it clicked. Instead of writing the same fields in five different interfaces, you just create one big master interface and slice it up however you need. Let me show you what I mean.

## The Problem I Kept Running Into

Say you have a `User` interface for your app:

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}
```

Now in different parts of the app you need slightly different versions of this. Maybe:
- A profile page that shows `name` and `email` but NOT the password
- A user card that only needs `id` and `name`
- A signup form that doesn't have `id` or `createdAt` yet because those get generated by the server

Before I knew about utility types, I was literally copy-pasting the interface and deleting fields. Which is terrible. If I rename `email` to `emailAddress` in `User`, I have to update every single copy. I missed one once and spent 30 minutes debugging.

## `Pick` — Just Take What You Need

`Pick<T, K>` lets you create a new type by picking specific fields from an existing type. That's it.

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}

type UserCard = Pick<User, "id" | "name">;
// gives you: { id: number; name: string }

type PublicProfile = Pick<User, "name" | "email">;
// gives you: { name: string; email: string }
```

Now `UserCard` is always based on `User`. If `User` changes, TypeScript will immediately tell me if something breaks. No more manual syncing.

## `Omit` — Just Remove What You Don't Want

`Omit<T, K>` is kind of the opposite. Instead of saying "give me these fields", you say "give me everything EXCEPT these fields."

```typescript
type SafeUser = Omit<User, "password">;
// gives you: { id: number; name: string; email: string; createdAt: Date }

type CreateUserPayload = Omit<User, "id" | "createdAt">;
// gives you: { name: string; email: string; password: string }
```

`SafeUser` is really useful when you're sending user data back from an API. You never want to accidentally send the password. With `Omit`, it's just... impossible to include it. TypeScript won't allow it.

## Using Them in Functions

This is where it gets actually useful in real code:

```typescript
function createUser(payload: Omit<User, "id" | "createdAt">): User {
  return {
    ...payload,
    id: Math.random(),
    createdAt: new Date(),
  };
}

function showUserCard(user: Pick<User, "id" | "name">): string {
  return `#${user.id} — ${user.name}`;
}
```

The function signatures tell you exactly what they expect. `createUser` won't let you pass an `id` (because the server creates it). `showUserCard` won't let you accidentally pass a password field. Everything is locked in at the type level.

## Quick Comparison

| What you want | Use |
|---------------|-----|
| Only a few specific fields from a big interface | `Pick` |
| Everything except one or two fields | `Omit` |
| Hide sensitive data like passwords or tokens | `Omit` |
| Build a minimal display/summary type | `Pick` |

## Conclusion

Honestly `Pick` and `Omit` are two of my favorite things in TypeScript now. Before I knew about them I had interfaces scattered everywhere with duplicated fields. Now I just define `User` once and derive everything else from it. When something changes, I change it in one place and TypeScript handles the rest. That's what DRY actually looks like in practice, and it's pretty satisfying once you get used to it.
